# 弹幕刮削

![main page](doc/page.png)

此插件根据文件匹配弹弹平台上的弹幕,将弹幕文件转换为ass格式字幕,用于实现在不支持弹幕播放的设备上模拟弹幕.

### 手动匹配与搜索
- 前端支持搜索弹弹番剧并手动匹配，可选“目录”或“单文件”范围；单文件仅作用于该文件。
- 手动匹配数据保存在目录下 `.dandan.anime.json`（旧 `.id` 会自动转换并删除）；单文件匹配存储在插件缓存。
- 手动匹配支持“集数偏移”：本地集数 + 偏移 = 弹弹集数。用于 TMDB 连续计数而弹弹按季重置的番剧，如本地 S02E13 对应弹弹第二季第 1 集则填 `-12`。
- 生成的弹幕文件为 UTF-8 无 BOM `.danmu.ass`，合并中文字幕时为原字幕事件补充 `{\blur10}` 提升可读性。

### 文件匹配规则
首先会尝试使用文件hash直接匹配文件,如果没有匹配到怎会尝试使用TMDB ID来进行匹配.

### 请求限速
弹弹play 对「文件识别」类请求有每日配额,中转服务器也按 IP 限速。插件对所有弹弹play 请求做了统一限速(30 请求/分钟),遇到 429/503 会自动退避,退避期间批量刮削会中止本批并留待下次执行——被限流不等于没有弹幕,因此不会计入重试次数。

「刮削并发数」控制的是本机同时处理的文件数(ffprobe 取时长、计算 hash、生成与合并字幕),和对服务器的请求速率是两回事,调小它并不能减轻服务器压力。



### 更新日志

-  v1.10.0: **「仅从B站获取」改为「优先使用B站弹幕」**——B站弹幕不足时自动回退全部来源。此前实测绝大多数剧集根本没有B站来源的弹幕，开启该选项会让大部分文件写出空弹幕并每 3 小时反复重试，而重试永远改变不了结果；回退只在原本就拿不到弹幕时触发，纯B站内容的行为不变。**修复集号越界导致弹幕串到别的作品**：弹幕ID编码为 `animeId*10000+集号`，此前集号无上界校验，集号 ≥10000 会进位到另一部作品、≥9000 会落进特典段，且全程无报错；现改为校验 `0-8999`，越界回退常规匹配。**支持第0集**（放送前特番/序章是合法集数，此前被静默改成第1集）。**修复目录手动匹配对 .strm 文件静默失效**，以及手动匹配目录仍白算 16MB 哈希 + ffmpeg 时长的浪费。**修复 .strm 文件缺少 TMDB ID 时的无限空转**：此前零请求即判失败并永久占据重试列表，现明确识别为「重试无法改变结果」并移出列表。**新增客户端限速**——所有弹弹play请求收敛到统一入口，令牌桶限速 30 请求/分钟并复用连接；遇到 429/503 时按 `Retry-After` 退避，且**不再把「被限流」误判为「没有弹幕」**，也不计入重试次数（此前服务端每拦一次，客户端反而多排一次重试）；服务端长时间限流时批量刮削中止本批、剩余文件留待下次执行；新增「刮削并发数」配置（只影响本机开销，对服务器的请求另有限速）。修复字幕匹配时 Ep1 会误命中 Ep10 的字幕；双集文件（如 E13-E14）改为按首集匹配弹幕；API 接口限制在配置的刮削路径内，拒绝越界读写；插件停止时可中止正在运行的批量刮削；`/update_path` 接口改为持久化保存；修复弹幕数据字段不足时的越界读取；前端轮询失败不再每 3 秒弹一次错误
